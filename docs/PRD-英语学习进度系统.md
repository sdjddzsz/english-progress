## 零、需求起因与产品哲学（必须先读）

用户在国庆假期中断数日后，发现**欠账堆积、复习量已无法按时完成**，而现有软件的复习计划由算法黑盒决定，他只能被动跟随；且单词本每一轮覆盖时间极长，进度永远追不上。

本产品的两条不可动摇的产品哲学：

1. **进度必须由用户掌控，不由算法掌控。** 所有影响进度的参数对用户开放、可改、改前有影响预览、改后可回滚。
2. **背单词不是目的，融会贯通才是目的。** 单词是输入原料，训练是出口；系统的一切设计服务于"把词变成能用的技能"，不服务于"背完多少词"的数字。

> **关于「掌握度降频默认开启」的哲学澄清（v1.0，Q3 决策）**：降频默认开启**不是**"算法替用户决定"。区别在于四点：① 规则是用户拍板的初始偏好并可在设置中随时关闭；② 判定标准完全公开透明（秒认 ≥2 次且无问题标签 → 稳固）；③ 有保底约束兜底——**秒认词在第 1 轮和最后 1 轮必现，中间轮才可跳**，任何词都不可能"消失"；④ 关闭开关立刻回到严格 100% 覆盖。这四点与市面软件"遗忘概率黑盒"有本质区别。架构师实现时必须保证：降频永远跳的是"中间轮"，首末轮不可跳。

> 架构师注意：除上述用户开启的降频规则外，任何其他"算法替用户决定今天学什么"的设计（遗忘曲线、出现概率、难度自适应排程）都必须默认关闭或显式可关，否则违背产品哲学。

## 一、产品目标

### 一句话目标

一个**进度完全由我掌控**的英语训练系统：用**期限内分层多轮覆盖**吃透六级全量词书（~7000 词），按「见词识意 → 听词联想 → 中→英联想 → 融会贯通」四阶把词汇变成可使用的技能，全程由**真实学习数据**驱动、**AI 在后台调参**，而不是由软件算法牵着走。

### 可度量目标

| 编号 | 目标 | 度量方式 | 目标值 |
|---|---|---|---|
| G1 | **进度可掌控** | 用户能在学习主页一屏内回答"各层还剩多少、当前第几轮、按当前速率哪天跑完"；且可在 3 次点击内修改任一进度参数 | 回答耗时 < 10 秒；参数修改 ≤ 3 次点击；改后 2 秒内出影响预览 |
| G2 | **期限内分层多轮吃透** | 按选定档位（推荐/保底）在 2026-12-05 前完成全部轮次，每词按其难度层的轮次 100% 覆盖 | 出师日 ≤ 2026-12-05；每轮覆盖率 100%；全部欠账事件 100% 被重排处理（无静默累积）；冲刺周（12-05~12-12）不排轮次 |
| G3 | **四阶训练体系落地** | 见词识意（P0）→ 听词联想（P1 首位）→ 中→英联想（P1 次位）→ 融会贯通（P2），每阶有可日更的训练形态 | P1 上线后，听词联想每日完成率 ≥ 80%；训练词源与当前复习队列重合率 ≥ 80% |
| G4 | **数据驱动、不自欺** | 前台零测试/零评分入口（模考除外，见 §4.8.3 锁定态）；能力评估全部由后台行为数据隐式计算 | 前台可见的"测验/评分/正确率/连续打卡/徽章"入口数量 = 0；后台每周产出 1 份能力诊断快照 |
| G5 | **AI 自治** | AI 通过结构化 API 直接读写学习数据并发布方案版本，人工只做确认/驳回 | AI 完成一次"读数据 → 提方案 → 生效"闭环，人工操作数 ≤ 1 次点击；无需导出数据到外部分析 |

> **v1.0 修正说明**：v0.1 的 G2 示例"3000 词 60 天 4 轮"与"日 50 词"存在算术冲突（3000×4÷60=200 hits/天 ≠ 50），且与 Q2 的 7000 词 / 55 天约束不符。v1.0 起调度校验以**时间预算**为约束（而非词数），详见 §4.4.6。

## 二、用户画像与核心场景

### 用户画像

| 维度 | 内容 |
|---|---|
| 身份 | 周思政，上海理工大学基础数学硕士研二（2025.09 – 2028.06） |
| 时间线 | 六级考试 2026-12-12；英语为五条并行主线之一 |
| 词汇现状 | **视觉词汇 ≫ 听觉词汇**（看认识的词远多于听认识的词），听力辨音是当前最弱项（Q6 决策依据） |
| 已有基础 | 视觉线（原单词 App）已有相当进度，部分词汇可能已掌握（占比待摸底校准） |
| 时间特征 | 双态：无实习期约 30h/周（五线分摊）；有实习后 12h/周。英语线原拆分两条子线：视觉线（30 分/天）+ 听力线（20–40 分/天），**均被本系统合并吸收** |
| 认知特征 | 数学训练背景，偏好**可控、可推导、可解释、无玄学**；对"算法替我安排"强烈反感 |
| 痛点 | ① 欠账不可控，越滚越大 ② 每轮覆盖时间过长，进度追不上 ③ 复习节奏由软件决定 ④ 市面软件配音带个人习惯、连读吞音 ⑤ 听音认不出词 |
| 明确反感 | 自测、打卡、连续天数、成就徽章、正确率、排行榜、AI 鼓励语——一切"自我感动"型设计 |

### 典型日场景

**场景 A｜通勤刷词（手机，10–30 分钟，碎片）**

地铁上单手操作。打开即进入今日队列（视觉模态 hit 为主），不做任何前置选择。卡片正面显示单词 + IPA 音标（常驻可见），点击即发音（神经 TTS，按音标驱动）。看完释义后**一次点击完成反馈标签**（L1 四选一）。断网可用：当日队列与音频预缓存。

**场景 B｜电脑前听词联想（20–40 分钟，对应原听力线）**

进入听词联想：听音（单词/短语/短句）→ 回忆词义 → 点 L1。犹豫超过 3 秒系统自动判"不会"（可修正）。复习即测试、无预习、无分数、无记录展示。这是每日的主力气训练（针对"听不出"这一最弱项）。

**场景 C｜电脑前产出训练（10–15 分钟，可选）**

见中文联想英文：给中文释义/语境提示 → 口头或拼写产出 → 翻转自查 → L1 标注。默认 15 词/天，可关。

**场景 D｜周末后台调方案（20–40 分钟）**

看四块：① 各层进度与本轮剩余 ② 欠账量与重排选项（每个选项配大白话解释） ③ 反馈标签分布与薄弱点清单 ④ AI 方案提案列表。逐条确认/驳回；必要时手动改层内轮次 / 截止日 / 每日预算。

**场景 E｜中断恢复（关键场景，也是本产品的起因）**

连续 N 天未学习（如国庆 5 天）→ 再打开时**不直接进入背单词**，而是弹出"欠账重排"面板：显示欠账量、原计划完成日、四种重排方案各自后果（每种配大白话）。用户选一个，债务清零后进入正常学习。**绝不静默累积欠账。**

**场景 F｜冲刺周（2026-12-05 ~ 12-12）**

词书已出师。模考入口若已由后台诊断解锁 → 每周 1 套真题限时完整模考（含作文），结果只在后台以诊断报告呈现；配合 AI 生成的作文模板包。词书轮次此周不再安排。

### 4.4 ★ 核心差异化：分层多轮覆盖复习调度模型（MRCS v1.0）

> 本产品与市面单词软件最根本的区别，也是起因痛点（"每轮覆盖时间极长、进度追不上、欠账无法完成"）的直接解法。**架构师可直接按本节实现。**

#### 4.4.1 模型定位与术语

| 术语 | 定义 |
|---|---|
| 词书 Book | 一本待攻克的词集合。本系统首本：六级全量 ~7000 词 |
| 难度层 Tier | 词书内的分层，**4 层**（Q1 决策）：T1 已掌握 / T2 熟词 / T3 半熟 / T4 生词。分层依据：词频 + 六级标记 + 用户已掌握度（摸底/历史反馈） |
| List | 层内的人工切块，默认 50 词/List，用于组织顺序与批量操作 |
| 轮次 Round | 对某个层完整走一遍。某词在其层的轮次安排内每轮被覆盖（hit）一次 |
| 覆盖 Hit | 一个词一次"被正面遇到并完成反馈"的事件。**v1.0：hit 有模态**（视觉=看词识意 / 听觉=听音联想），同一轮次的 hit 可分配不同模态 |
| 计划 Plan | { 词书, 各层轮次 tier_rounds, 截止日 deadline(默认 2026-12-05), 冲刺周起 sprint_start(默认 2026-12-05), 每日分钟预算, 轮间隔下限, 模态比例, 降频开关 } |
| 档位 plan_mode | **推荐计划 / 保底计划** 两档（Q2 决策），区别在层内轮次（见 4.4.6） |
| 日程 Schedule | Plan 展开后的每日词表（哪天、哪些词、第几轮、什么模态） |
| 欠账 Overdue | 应完成但未完成的 hit 集合 |
| 冲刺周 Sprint | deadline 至考试日之间的窗口（12-05~12-12）：不排轮次，只排模考（若解锁）+ 作文模板 |

**核心承诺：每词按其层的轮次数被覆盖，跑完即"出师"，有明确终点（2026-12-05）。** 不存在"旧词无限回潮"。

#### 4.4.2 与记忆曲线的对比

| 维度 | 市面软件（记忆曲线） | 本产品（MRCS v1.0） |
|---|---|---|
| 出现时机由谁决定 | 算法按遗忘概率决定，用户不可预知 | 由**层轮次窗口**决定，用户可预知、可改 |
| 是否有终点 | 无终点，旧词不断回潮 | **有终点**：层内 R 次 × 100% 覆盖，12-05 前出师 |
| 每轮覆盖时长 | 横跨数月 | 用户自设层内轮次与预算，推荐档 ~18 天/轮 |
| 欠账处理 | 无限累积，越滚越大 | 阈值触发重排，四选一（配大白话），**债务清零** |
| 掌握度的作用 | 决定出现概率（黑盒） | **用户开启的降频规则**（v1.0 默认开）：稳固词中间轮可跳，首末轮必现；标准公开、可关 |
| 校验依据 | 无（或黑盒） | **时间预算校验**：日预算分钟数为准，不通过即拒绝/降级 |
| 可控性 | 黑盒 | 参数全开 + 影响预览 + 版本回滚 |

#### 4.4.3 调度算法（确定性、可解释）

**输入**：各层词量 W_t 与层轮次 R_t、总窗口天数 T（deadline − start，冲刺周除外）、每日分钟预算 budget、avg_hit 秒数、轮间隔下限 gapMin、List 划分、模态比例。

**Step 1 — 时间校验（v1.0 核心变更：以时间为准，不以词数为准）**

```
totalHits = Σ_t ( W_t × R_t )        ← 降频开启时按 §4.4.5 折减
dailyHits = ceil(totalHits / T)
dailyMinutes = dailyHits × avg_hit_sec / 60
通过条件：dailyMinutes ≤ budget
```

- `avg_hit_sec` 默认 **12 秒**（含看词/听音、L1 点击、偶尔 L2/L3；听觉 hit 略长、视觉秒认略短，已折算进均值）。**首周用真实 reaction_ms 数据校准**，此后每月重校——估错不用拍脑袋，用数据修正（数据驱动哲学的落点）。
- 校验不通过 → **拒绝该档位**，进入降级路径（§4.4.7）。

**Step 2 — 划分层轮次窗口**

各层在其 T 窗口内等分 R_t 段（可不等分，用户可逐层手调每轮天数）；任一轮窗口不得短于 `W_t / maxDailyHits` 天（物理下限）。其中 `maxDailyHits = floor(日预算分钟 × 60 / avg_hit_sec)`（v1.1 明确来源：由时间预算与单 hit 均时推导，不单独配置）。

**Step 3 — 生成每日词表**

对每一天，从各层"本轮尚未覆盖"的词中取额度（跨层混合时按层配比分配，避免某层长期饥饿）：

- **跨 List 轮转**：List 内连续（同批词一起进入语境素材），List 间按"每轮起始偏移"轮转。
- **轮内乱序**：每轮内部 List 访问顺序打乱一次（种子=轮次号，可复现）。
- **模态分配（v1.0 新增）**：每个 hit 按层的模态比例决定呈现形式（默认 T1 听 70%/视 30%，T2 听 50%，T3 听 30%，T4 听 20%——视觉为主分层、听觉为辅，比例用户可改）。**这一条把原"听力线 20–40 分/天"吸收为调度的一部分**：听力训练就是部分 hit 以听觉模态出现，不再是额外任务。T4 生词以视觉为主（先认形），T1 熟词以听觉为主（补最弱项）——正好对准"视觉词汇 ≫ 听觉词汇"的现状。
- **间隔约束**：同词相邻两次 hit 至少间隔 `gapMin`（默认 = 轮窗口 × 0.6）。与遗忘曲线无关，纯覆盖均匀性；冲突时顺延该词到最近合法日。

**Step 4 — 日程可解释**

任意一天队列可点开"为什么是这些词"：
> "第 2 轮 · T3 半熟层 · List 7 · 本轮第 4 天 · 本日 306 词（视 214 / 听 92）· 词 A 上次出现在 3 天前（第 1 轮·视觉）"

#### 4.4.4 ★ 欠账处理（起因痛点的直接解法）

**规则 1：欠账不消失、不翻倍、不静默累积。** 未完成 hit 进 overdue 池，原样保留。

**规则 2：阈值强制触发重排。** `|overdue| > 2 × dailyHits`，或连续 3 天未学且欠账 > 0 → **打开应用先弹重排面板**，不许直接进背单词。

**规则 3：四种重排策略，每个配大白话（v1.0，Q4 决策），用户选，AI 可给推荐**

| 策略 | 机制 | 大白话（面板原文） | 后果 | 适用场景 |
|---|---|---|---|---|
| **A 展期 Extend** | 本轮窗口后延，后续轮次顺延 | 「**做不完就往后顺延**：整体时间拉长，每天量不变，质量不缩水。」 | 总工期 +Δ 天，完成日推迟 | 时间有弹性，想保质保量 |
| **B 压缩 Compress** | 保持总工期，欠账摊入本轮剩余天+下一轮 | 「**日子不能延，就每天多背一点**：总量和时间都不变，短期内加量。」 | 日额度上浮至时间校验上限 | 截止日固定，不能延期 |
| **C 降轮 Drop Round** | 某层 R_t ← R_t − 1（保底 2） | 「**实在赶不上，就少过一遍**：比如 3 遍改 2 遍，完成时间不变。」 | 该层总 hit 减少 W_t 个 | 进度严重落后且时间不可延 |
| **D 子集冻结 Freeze** | overdue 中"已稳固"的词移出本轮，末轮复查一次 | 「**已经会的先放一放**：把欠账里其实已经掌握的词移出本轮，最后一遍时再确认一次。」 | 欠账显著下降，工期不变 | 欠账里大部分其实已经会了 |

**"稳固"判定**（驱动 D 与降频）：L1 `秒认` 连续 ≥ 2 次 且 无任何 L2 问题标签 且 在听觉模态 hit 中被正确识别 ≥ 1 次 → 稳固。

**规则 4：重排即债务清零**，记变更日志（策略、原完成日、新完成日）。

**规则 5：允许显式部分放弃（反完美主义）。** 可对 overdue 子集勾选"本轮跳过"→ 标 `deferred`，只在末轮出现一次。**延伸（v1.0）**：整层冻结（如冻结 T1 整层）是"显式放弃"的层级化推广，属 Require 级提案，需用户显式批准——它是**计划创建/重排时的显式决策**，不违反 Q3 保底约束（该约束约束的是学习过程中被判秒认的词）。

**规则 6（v1.0）：deadline 硬约束。** 展期 A 不得突破 2026-12-05（冲刺周属六级抢分安排，不可侵占）。若 A 达到 deadline 仍不够 → 系统明确提示只能走 B / C / D 或上调预算。

#### 4.4.5 掌握度降频（v1.0：默认开启，Q3 决策）

| 项 | 设计 |
|---|---|
| 默认状态 | **开**（用户拍板；设置页可一键关闭回到严格全量覆盖） |
| 判定 | 稳固（同 §4.4.4 判定） |
| **保底约束（硬约束）** | **稳固词在第 1 轮和最后 1 轮必现，仅中间轮可跳。** 调度器实现必须保证首末轮不可跳 |
| hits 折减 | 稳固词的 hits 从 R_t 降为 2（首 + 末）；R_t=2 时无折减空间 |
| 哲学定位 | 不是算法替用户决定：规则透明、可关、判定标准公开、有保底约束（见 §零 澄清框） |
| 关闭后 | 立即恢复全量覆盖，重排并出影响预览 |

#### 4.4.6 ★ 推荐计划 / 保底计划（v1.0，Q2 决策）

**输入约束（来自用户）**：
- 截止日 2026-12-05（T≈55 天，冲刺周 12-05~12-12 不排轮次）。
- 双态时间预算：无实习期总 30h/周；有实习后 12h/周（五线分摊）。按英语线占 1/5 估：无实习 ≈ 6h/周 ≈ **51 分/天**；本系统吸收原视觉线（30 分/天）+ 听力线（20–40 分/天）→ **校验基准取 60 分/天（可调区间 50–70，设置页可改）**。
- 该 1/5 配比是**假设**，用户可在设置中改实际配比；改后校验结果即时重算。

**两档定义（层内轮次不同）**：

| 档位 | T1 已掌握 | T2 熟词 | T3 半熟 | T4 生词 | 说明 |
|---|---|---|---|---|---|
| **推荐计划** | R=2（首末轮） | R=2 | R=3 | R=3 | 熟词少过、生词多过；对准"视觉强、听觉弱" |
| **保底计划** | R=2 | R=2 | R=2 | R=2 | 全层 2 遍，最稳最轻 |

**敏感性算术（avg_hit=12s；层分布为摸底前假设 25/35/25/15，摸底后自动更新）**：

| 方案 | 总 hits | hits/天 | ≈分钟/天 | 50 分预算 | 60 分基准 | 70 分预算 |
|---|---|---|---|---|---|---|
| 全层 R=3（不降频，参照项） | 21000 | 382 | 76 | ✗ | ✗ | ✗ |
| 推荐计划（25/35/25/15） | 16800 | 306 | 61 | ✗ | ⚠ 临界 | ✓ |
| 推荐计划（摸底后 T1≥30%、T4≤10%） | 16450 | 300 | 60 | ✗ | ✓ | ✓ |
| **保底计划（任意分布）** | 14000 | 255 | 51 | ⚠ 临界 | ✓ | ✓ |
| 保底计划 + 冻结 T1 整层（25%） | 12250 | 223 | 45 | ✓ | ✓ | ✓ |

> 读法：**推荐档能否通过，取决于摸底后 T1 占比**——用户已掌握的部分越多，越可行。这正是"降频默认开"的算术意义：全量 R=3 不降频（第一行）在 55 天内无论什么预算都过不了，只有分层 + 降频才让 7000 词 × 多轮变得可行。**G2 的度量以选定档位 + 时间校验为准，不再使用 v0.1 的"3000 词 60 天 4 轮"示例。**

**两档均须通过 MRCS 时间校验后才呈现给用户**；推荐档临界（±5%）时显示黄色警告并附三个选项（见降级路径）。

#### 4.4.7 校验不通过的降级路径（明确写出，架构师照做）

```
推荐计划不通过

        ├→ 通过 → 呈现保底计划
        └→ 不通过 → Require 级三选一（必须用户确认）：

  └→ 任何档位均不通过 → 系统建议切换「维持模式」：
```

### 4.5 发音：主轨神经 TTS + 兜底机械 IPA（v1.0 架构变更，Q5 决策）

> **用户明确不能接受机械音**（v0.1 的"机械 IPA 主轨"方案被否决）。v1.0 反转双轨：

| 项 | 设计 |
|---|---|
| **主轨** | **高质量神经 TTS + SSML `<phoneme>`(IPA) 精确控制**。发音仍 100% 由音标驱动——IPA 以 phoneme 标签注入 SSML，合成引擎按音标逐音素发音，杜绝"配音者个人习惯"；同时音色自然，用户可接受 |
| 单词模式 | 逐词合成、词间停顿，SSML 层禁用自动连读/弱读/吞音；重音与音节分隔可见，**点击单个音节可只听该音节** |
| 例句模式 | 允许自然韵律与连读（否则极不自然），另提供「逐词慢读」按钮（逐词按 IPA、词间留白）——**注意区分**：单词朗读的"严格不连读"是发音正确性要求；例句/听词联想素材里的连读是**真实考试的听觉输入**，两者不矛盾 |
| **兜底轨** | **espeak 类机械 IPA 合成**（本地/开源，无需联网）。云 TTS 不可用 / 超时 / 未配置时自动回退，后台记录回退事件；前台轻提示一次，**不阻断学习** |
| **Provider 插拔接口** | TTS 供应商做成可插拔配置：端点 + key + 音色即可切换（Azure / 其他云 TTS / 自建 / OpenAI 兼容端点）；**默认建议 Azure 语音服务免费额度** |
| **待确认状态（重要）** | 云 TTS 供应商**待用户申请确认**（涉及外部服务开通，按需求 11 需用户批准）。**未确认前：TTS 配置页留空但接口完备**，系统以兜底轨（espeak）运行，设置页醒目提示"主轨音质待激活，请配置云 TTS" |
| 存疑入口 | L3「发音存疑 / 发音错误」→ Issue → 后台待处理清单，可批量重录 / 换供应商 / 修音标 |

### 4.6 ★ 反馈标注分类体系（对应需求 6）

> 设计原则：**一次点击即走，不给空文本框。** 三层结构；L1/L2/L3 同时服务于视觉模态（见词识意）与听觉模态（听词联想）。

#### L1 认知状态（必选，单选，一次点击完成并跳下一词）

| 标签 | 含义 | 语义约定 |
|---|---|---|
| 😀 **秒认** | 看到就认识（视觉）/ 听到就反应（听觉），< 1 秒（视觉）或 < 3 秒（听觉） | 连续多次 → 判"稳固"（降频与冻结的依据） |
| 😐 **认得** | 想了一下，认出来了 | 正常通过 |
| 😵 **见过想不起** | 有印象但想不出释义；**听觉模态下：犹豫超 3 秒系统自动判此档** | 后台重点信号 |
| ❌ **不认识** | 完全没见过 / 听了毫无反应 | 后台重点信号 |

> 系统自动记录反应时长（毫秒），作为隐式评估与 avg_hit 校准输入，不展示给用户。

#### L2 问题定位（可选，chips 多选，最多 3 个）

| 分类 | 标签 |
|---|---|
| **词义** | 词义记不住 · 中文释义太抽象/易混 · 多义项分不清 |
| **词形** | 拼写/词形记不住 · 形近词混淆（选后给候选词 Top5，点选记混淆对） · 词根词缀不熟 |
| **发音** | 发音读不准 · 重音位置记不住 · **听的时候听不出这个词**（听觉模态核心标签） |
| **用法** | 词性判断错 · 搭配/介词不会用 · 知道意思但造句造不出 |
| **语境** | 例句看不懂 · 阅读里没反应过来 · 听力里没反应过来 |
| **素材** | 释义有误 · 例句不当 · 音标有误（→ 自动进 Issue 清单） |

#### L3 处置动作（可选，直接改变调度）

| 标签 | 效果 |
|---|---|
| **加练** | 本轮再多出现 1 次（hit +1，计入时间校验） |
| **暂缓** | 本轮不再出现，移到末轮复查 |
| **跳过本轮** | 标 `deferred`，本轮跳过，末轮出现一次 |
| **重点收藏** | 加入"重点集"，后台可单独生成素材 |
| **发音存疑 / 发音错误** | 生成 Issue，进后台待处理清单 |
| **释义/例句存疑** | 生成 Issue，进后台待处理清单 |
| **备注**（自由文本，非必填，≤60 字） | 供 AI 读取 |

#### 反馈如何被后台拉取

会话结束 → 生成 **session summary**（hit 数、L1 分布、L2 Top、新增混淆对、新增 Issue、平均反应时长、模态分布）→ 手动触发（会话结束页「让 AI 看这批反馈」）或自动（默认每日一次，P1-08）。

### 4.7 ★ 训练体系：四阶优先级（v1.0 重排，Q6 决策）

> v0.1 的"听说读写四项并行"框架被用户否决重排。新框架按**用户紧迫性**排序——背单词页（见词识意）是现有主力，**听词联想**直击"视觉词汇 ≫ 听觉词汇"这个最弱项，融会贯通（四项语境训练）降为 P2。

| 阶 | 优先级 | 名称 | 形态 | 每日默认 | 与调度关系 |
|---|---|---|---|---|---|
| 一 | **P0** | **见词识意** | 背单词页：看词 + IPA → 释义 → L1/L2/L3 反馈 | 按计划额度（视觉模态 hit） | 即词书轮次本体 |
| 二 | **P1 第一位** | **听词联想** | 听音（单词/短语/短句，六级语速）→ 回忆词义 → L1 标注。**复习即测试**：无预习、先听后想。**犹豫超 3 秒自动判"不会"**（计时器可见，可修正）。吸收原《六级听力_最终执行版_20260920》全部设计要点 | 20–40 分钟（原听力线预算） | **hit 与词书轮次共享调度**（模态分配，§4.4.3 Step 3），不是额外任务 |
| 三 | **P1 第二位** | **见中文联想英文** | 中文释义/语境提示 → 口头或拼写产出 → 翻转自查 → L1 标注 | 15 词（可关） | 可选附加配额，计入时间校验 |
| 四 | **P2** | **融会贯通**（听说读写四项语境训练，v0.1 的四项最小形态内容全部保留于此） | 听：辨词听写+跟读；说：造句口述；读：语境短文；写：仿写造句 | 各项可日更，用户自选 | 可选附加配额；素材词源 100% 来自当前队列 |

**听词联想的三条设计铁律（来自原听力线文档，原样吸收）**：
1. **复习即测试**——出声就回忆，没有"先看释义再听"的预习路径。
2. **犹豫超 3 秒 = 不会**——不纠结、不自欺，计时器在前台可见，超时自动标 😵。
3. **不设指标、不做记录**——前台零正确率、零听懂百分比、零历史曲线；**后台仍落库**（供调度与 AI 使用），这是与反自测规则一致的关键边界（详见 §4.8.2 说明）。

**为什么听词联想排第一**：用户视觉词汇已有强基础（原视觉线积累），而听觉词汇远落后于视觉词汇——六级听力听不出词是当前最大失分风险。T1/T2 层 hit 以听觉模态为主，正好用"已经认识的词"训练"听出来"的能力。

**四阶共同规则**：
1. 训练词源强制来自当前复习队列（融会贯通的机制化）。
2. 全部可关/可跳，用户决定练什么。
3. 全部无得分、无评级、无星级、无正确率（前台）。
4. 素材标注来源：`真题原声/真题语料` / `AI 生成` / `TTS 合成` / `用户导入`。

**"贯通"的可度量信号**（后台，非前台）：某词视觉 hit 稳固 **且** 听觉 hit 正确识别 **且**（P2 后）在说/写中正确使用 → 标 `已贯通`。后台输出"各层贯通率"，仅诊断口径。

### 4.8 ★ 反自测产品规则（对应需求 9 + Q8 修订）

> 用户明确要求：**不要安排"自测"之类的自我感动行为，测试类行为交由后台评判。**

#### 4.8.1 明确「不做」清单

| ❌ 不做 | 原因 |
|---|---|
| 用户可见的"测试 / 测验 / 自测 / 闯关"日常入口 | 直接违反需求 9 |
| 单词拼写填空、选择题、判断题等日常测验题型 | 测试不是学习 |
| 用户可见的"正确率 / 得分 / 评级 / 掌握度百分比"数字 | 会为数字而学，不是为能力而学 |
| 连续打卡天数、打卡日历、成就徽章、等级、排行榜 | 典型自我感动设计 |
| "今日目标完成度"圆环 / 进度条动画 / 完成烟花 | 激励型视觉绑架 |
| 学习时长炫耀型统计 | 时长是诊断输入，不是成果 |
| AI 生成的鼓励语 / 鸡汤 | 用户明确反感 |
| 每日推送提醒"该背单词了" | 干扰（可在设置中由用户主动开启） |

> **边界澄清（v1.1）**：**轮内覆盖进度允许静态展示**（如主页"List 7 · 剩 38 词"、"34/50 List"这类进度信息），它属于调度信息而非激励设计；**激励型完成度展示禁止**（完成度圆环、进度条动画、完成百分比、庆祝/烟花效果）。判别标准：静态、无情绪化动效、服务于"还剩多少"的可控感 = 允许；动态渲染、营造成就感 = 禁止。

#### 4.8.2 隐式评估与"不做记录"的边界说明（v1.0 新增，需向用户复述确认）

听词联想的「复习即测试」**不属于**自测禁令，理由：它没有分数、没有对错展示、没有记录向用户展示——**回忆这个动作本身就是学习**，"犹豫 3 秒=不会"只是反馈判定规则。与"不做记录"的边界解释为：**前台零指标零记录展示；后台仍落库**（反应时长、L1 标签、模态表现），否则调度器与 AI 失去输入、降频与重排无法工作。此解释需向用户复述确认（见 §8.3 R6）。

**后台隐式评估信号**：反应时长分布（首次 vs 重现）· L1 标签迁移 · L2 类别占比 · 混淆对 · 复现提升率 · **模态迁移度（视觉表现 vs 听觉表现的差距曲线——v1.0 核心）** · 加练请求率。

**后台产出（P1-04 能力画像快照）**：词级状态（未接触/生疏/熟悉/稳固/已贯通）· 薄弱点清单（高频想不起词、Top 混淆对、L2 类别占比、视觉/听觉差距）· **不产出**总分、正确率、排名、评级、预计考试分数。

#### 4.8.3 ★ 模考：不算自测，锁定态开放（v1.0，Q8 决策）

**模考 ≠ 自测**，区别理由（写明，防止实现时被误删）：
- 自测/测验/打卡**无外部效度**——它不对应任何真实世界的检验，只提供"我在努力/我在进步"的即时满足，即"自我感动"。
- **模考有明确外部效度**——面向 2026-12-12 真实考试，限时、完整流程、真题，目的是暴露应试问题（时间分配、题型策略、作文手速），是**诊断工具**而非日常学习动作。

**锁定态设计**：

| 项 | 设计 |
|---|---|
| 默认状态 | **锁定**。入口灰置，仅显示一句："由后台诊断解锁" |
| 解锁规则 | 由 **AI 基于学习数据制定**（例如词书覆盖率、欠账归零天数、各层稳固率、听觉识别率等信号的组合阈值），**不预设固定分数线**；规则作为提案 → 用户确认（Confirm 级）→ 生效；用户也可随时手动锁定回退 |
| 解锁后 | **每周 1 套真题**限时模考，与总排期六级抢分阶段一致；冲刺周（12-05~12-12）必排 |
| 结果呈现 | 只在**后台**以诊断报告呈现：题型得分分布、时间分配、错误归因；**首页不展示总分** |
| 依赖 | 真题卷库（papers 集合）留待真题模块（P2）；**首版模考以 AI 生成素材充当**（R7 已定口径：真题语料首版不做、AI 生成素材代替），`MockExamRecord.paper_ref` 为外部引用占位 |

## 六、数据模型初稿（给架构师的输入）

> 字段名为英文（便于实现），说明为中文。不要求最终精度，架构师可增删索引与中间表。

### 6.1 核心实体

| 实体 | 关键字段 | 说明 |
|---|---|---|
| **User** | id, email/phone, created_at, timezone, settings(json) | 单用户系统，按多用户建模 |
| **Book** | id, user_id, name, source(`builtin`/`import`/`manual`), word_count, tier_count, list_size, status(`active`/`finished`/`archived`) | 词书；首本=六级全量 ~7000 |
| **Word** | id, lemma, ipa, pos, senses(json), examples(json), frequency, tags(四六级/考研) | 词本体，来自 ECDICT 或自定义 |
| **BookWord** | id, book_id, word_id, list_no, order_in_list, **tier(1–4)**, tier_updated_at, status(`normal`/`deferred`/`mastered`/`steady`) | 词书-词关联；**难度层在此** |
| **StudyPlan** | id, book_id, **tier_rounds(json, 如 {1:2,2:2,3:3,4:3})**, **plan_mode(`recommended`/`fallback`)**, start_date, **deadline_date(默认 2026-12-05)**, **sprint_start_date(默认 2026-12-05)**, **daily_budget_min(默认 60)**, **avg_hit_sec(默认 12, 可校准)**, gap_min_days, **modal_ratio(json, 逐层视/听比)**, **mastery_decay_enabled(默认 TRUE)**, version, status | 复习计划（版本化） |
| **PlanRound** | id, plan_id, tier, round_no, start_date, end_date, coverage_target, covered_count, status | 层内轮次 |
| **Hit（复习任务）** | id, plan_id, word_id, tier, round_no, scheduled_date, **modality(`visual`/`audio`)**, status(`pending`/`done`/`overdue`/`deferred`), completed_at | 一次覆盖任务；**含模态** |
| **Session** | id, user_id, type(`vocab_visual`/`vocab_audio`/`cn_to_en`/`integrated`/`mock_exam`), started_at, ended_at, device, hit_count | 学习会话 |
| **SessionSummary** | id, session_id, user_id, hit_count, l1_dist(json), l2_top(json), new_confusion_pairs(json), new_issues(json), avg_reaction_ms, modality_dist(json), created_at, pushed_to_ai(bool) | 会话摘要，会话结束时生成；供 AI 拉取（P1-08 自动推送）与后台审计 |
| **Feedback** | id, hit_id, session_id, word_id, l1_state, reaction_ms, l2_tags(json), confusion_word_id, l3_actions(json), note, created_at | 反馈标记，每次 hit 一条 |
| **ConfusionPair** | id, user_id, word_a, word_b, count, last_at | 形近词混淆对 |
| **Issue** | id, word_id, type(`pronunciation`/`definition`/`example`/`ipa`), note, status(`open`/`resolved`), created_at, resolved_at | 存疑待处理清单 |
| **PronunciationLog** | id, word_id, **engine(`neural_tts`/`ipa_espeak`)**, success, fallback_used, error, created_at | 发音引擎成功/回退日志 |
| **TTSProviderConfig** | id, user_id, provider, endpoint, api_key_ref, voice, ssml_phoneme_enabled, **status(`pending_user_setup`/`active`/`error`)**, fallback_engine(`ipa_espeak`) | TTS 插拔配置；**默认 pending_user_setup** |

| **TrainingRecord** | id, session_id, item_id, user_output(json), word_hits(json), created_at | 训练记录（无分数字段） |
| **TierSnapshot（摸底记录）** | id, user_id, sampled_word_ids(json), responses(json), computed_tiers(json), calibrated_at | 初始摸底与分层校准 |
| **MockExamRecord** | id, user_id, paper_ref, taken_at, unlock_rule_id, diag_report(json), created_at | 模考记录（仅诊断报告，后台渲染）；**paper_ref 为外部引用占位，指向 papers 集合（真题卷库），因 R7 决策"真题语料首版不做、AI 生成素材代替"，papers 集合留待真题模块（P2），首版模考以 AI 生成素材充当 |

| **AIProviderConfig** | id, user_id, provider_type(`workbuddy`/`openai_compatible`), base_url, model, api_key_ref, is_default, last_test_at | AI 端点配置 |

### 6.2 关键关系

- `User 1—N Book 1—N BookWord(tier) N—1 Word`
- `Book 1—N StudyPlan 1—N PlanRound(tier) 1—N Hit(modality)`
- `Hit 1—1 Feedback`；`Feedback` 可产生 `ConfusionPair` 与 `Issue`
- `Session 1—N Hit / TrainingRecord N—1 TrainingItem`
- `User 1—N MockExamRecord N—1 MockUnlockRule`
- `StudyPlan 1—N AIProposal / PlanVersion`

### 6.3 架构师必须遵守的字段约束

| 约束 | 说明 |
|---|---|
| Feedback / TrainingRecord / MockExamRecord **不得有** score / accuracy / rating 的**前台可见通道**（MockExamRecord 的诊断报告仅后台渲染） | 反自测规则的物理保证 |
| Hit.status 必须有 `overdue` 与 `deferred` | 欠账与显式放弃是一等公民 |
| StudyPlan.mastery_decay_enabled **默认 TRUE**（v1.0） | Q3 决策；设置可关 |
| 调度器硬约束：稳固词**首末轮必现**，仅中间轮可跳 | Q3 保底约束，不可妥协 |
| 展期重排**不得突破 deadline_date** | 冲刺周不可侵占（Q2） |
| AIProposal 必须含 reason 与 changes(diff) | 可解释性要求 |
| TTSProviderConfig.status 默认 `pending_user_setup` | Q5：供应商待用户确认 |
| **多端并发写冲突**：hit 使用**确定性 ID 幂等**（同端离线补传/跨端重复提交不产生重复记录）+ **last-write-win**（同 hit 多端写入取最后一条）+ **5 秒轮询同步** | 多端并发（手机/电脑同时在线）下的数据一致性设计约束 |

## 七、AI 框架需求（对应需求 10）

> 目标：AI 能在产品内直接上手工作，不需要每次把数据拉回 WorkBuddy 人工分析。

### 7.1 AI 能力清单

**读取类（只读，低风险）**：`get_study_records`（含模态/反应时长）· `get_feedback_stats` · `get_overdue_stats` · `get_word_stats`（含视觉/听觉双模态表现）· `get_book_progress`（各层）· `get_training_records` · `get_pronunciation_issues` · `get_tts_provider_status` · `get_ability_snapshot` · `query_words`（按层/标签/状态/混淆次数筛选）

**写入类（按风险分级）**：

| 能力 | 风险 | 说明 |
|---|---|---|
| `update_plan_params` | 高 | 改层轮次/截止日/日预算/模态比例 |

| `switch_plan_mode` | 高 | 推荐 ↔ 保底切换 |
| `batch_defer_words` | 中 | 批量跳过本轮（>20% 升级为高） |
| `adjust_word_frequency` | 中 | 单/少量词加练或降频 |
| `recompute_word_tiers` | 中 | 摸底校准/定期重分层（批量 >10% 词需确认；≤10% 自动执行并记日志） |
| `move_words_between_lists` | 中 | 调 List 归属 |
| `update_mock_unlock_rule` | 中 | 制定/修改模考解锁规则（Q8：不预设固定分数线，基于学习数据） |
| `mark_word_status` | 中 | 标 mastered/steady/deferred/重点 |
| `create_training_material` | 低 | 生成听词联想/中→英/融会贯通素材（必须绑定当前队列词） |

| `resolve_issue` | 低 | 处理存疑清单 |
| `create_ability_snapshot` | 低 | 生成能力画像 |
| `annotate_word` | 低 | 补释义/例句/助记 |

| 级别 | 覆盖能力 | 生效方式 |
|---|---|---|
| **Auto（自动）** | 生成素材、补发音、处理 Issue、生成能力画像、补释义、小批量重分层（≤10%）、**avg_hit 首周/月度自动校准**（属计划参数变更，落 PlanVersion 快照、可回滚，v1.1 明确） | 直接落地，ToolCallLog 可回溯 |
| **Confirm（需确认）** | 日预算 ±20% 内调整、单词频次调整、List 归属、批量 defer ≤20%、重分层 >10%、模考解锁规则、冲刺周材料包 | 推给用户一键确认/驳回；可设"N 分钟无操作按建议执行"（默认关闭） |
| **Require（必须确认）** | 改层轮次、改截止日、降轮、执行重排策略、整层冻结、切档位、批量 defer >20%、开/关降频 | **必须人工点确认，永不自动执行** |

### 7.3 方案版本化与回滚

- 每次生效变更生成新 `PlanVersion`（完整快照）；记录谁改的（user/ai/system）、为什么（reason）、改了什么（diff）；可回滚任意版本，回滚本身也记版本。
- AI 提案被驳回时记录驳回，用于评估 AI 是否在制造形式主义。

### 7.4 触发方式

手动（「让 AI 看这批反馈」「生成本周方案」）· 事件（欠账超阈值、某 L2 标签 7 天激增 50%、混淆对新增 ≥5、TTS 回退率异常）· 定时（P1：每日会话汇总、每周日周度方案）。

### 7.5 端点与免密钥

默认 WorkBuddy 免密钥 LLM（零配置）；可切换任意 OpenAI 兼容端点（含用户本机 9999 网关），可测试连通性。AI 调用产品内结构化 API + 工具清单，与模型厂商解耦。

### 7.6 防"形式主义"的硬约束

1. 每次工具调用写 `ToolCallLog`（输入/输出/是否生效/是否被驳回）。
2. AI 提案**必须附 reason**，无理由提案系统直接拒绝落地。
3. 后台「AI 有效性面板」：提案采纳率、驳回率、生效后 7 天指标变化（欠账是否下降、L1 分布是否改善、视觉/听觉差距是否收窄）。
4. 同类提案连续被驳回 3 次 → 自动降级为"仅建议"（P2）。
