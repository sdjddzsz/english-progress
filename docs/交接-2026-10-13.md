## 四、★★ 词书口径（用户 2026-10-13 拍板）

**最终 8296 词** = ① 池：`tag ∈ {cet6,cet4,ky,ielts}`（7445）+ ② 补偿：`oxford=1` 或 `collins≥3` 的**无标签**词（851，去重后）。所有 cet6 词必收。

**为什么不是「按词频取前 7000」** —— 实测踩过三个坑：
1. **ECDICT 的 cet 标签不可信**：`use(frq=92)` / `read(337)` / `live(210)` / `wind(1092)` / `present(817)` /
   `minute(308)` / `second(381)` / `close(649)` 这些高频多读音词，ECDICT **只标 zk gk，完全没标 cet4/cet6**。
   纯按标签取 ⇒ 这批词整批漏掉 ⇒ 「不同读音当不同词」的需求在数据层就没有素材。
2. **ECDICT 的 `frq` 不是可用词频**：全表 17.6 万可用词里 `frq≥500` 的有 3.7 万个，毫无区分度；
   `use=92`、`read=337` 这些真实高频词的值低得排不上去。
   ⇒ 按 frq 补词这条路**已废弃**（试过：池子炸到 34092 词且仍漏掉 use/read）。
3. **纯按词频取前 N 会切掉 record/object/produce**：它们 frq 值（record=516）排不进前 7000，
   但恰恰是最该练的多读音词 ⇒ 改成「**cet6 全收 + 词频补齐**」。

**实测词库规模**：`eligible 8296` / `picked 8296` / `mustIncluded(cet6) 5340` / `cmuHit 8210` /
`multiPron 1209`（多读音词）/ `totalSenses 16822`（义项总数）。

**超集关系（重要）**：新词书 ⊇ 旧 5407 词全部 lemma ⇒ `wordId = word_<lemma>` 不变
⇒ **已有 hits / feedbacks 不产生孤儿**，重建词书不需要清学习记录。已由 `tests/data/rebuild.test.ts` 钉死。

## 五、★★ 数据层 v3 格式（`seed-cet6.json`）

字段顺序：`lemma, arpabet?, ipa, senses[], sensesDetail[], translation, exchange?, examples[], frq, tags[]`

- `sensesDetail`：**新增的义项级结构**。`{senseId, lemma, pos, zh, pronunciationKey, arpabet, ipa}`。
  `pronunciationKey` = 该义项绑定的 arpabet（无读音时 `NO_PRONUNCIATION`）——**判定「是不是同一个词」的依据**。
- `exchange`：**新增**，ECDICT `exchange` 解析结果（p/d/i/3/r/t/0/1/s → 过去式/过去分词/…）。
- ⚠ **两份种子文件现已完全一致**（历史上不一致，导致云端拿到旧式 IPA；本次一并消除）。
  重新生成时**两条命令都要跑**（public + src），守门用例 `tests/qa/basics.test.ts` 会断言二者 `toEqual`。

**重建词书命令**（需要 ECDICT 全量 CSV 65MB，本机临时副本 `.ecdict.tmp.csv` 已 gitignore）：
```bash
npx tsx src/data/seed/buildSeed7000.ts --ecdict .ecdict.tmp.csv --out public/seed-cet6.json
npx tsx src/data/seed/buildSeed7000.ts --ecdict .ecdict.tmp.csv --out src/data/seed/seed-cet6.json
```

## 七、★★ 义项级判定的语义边界（改前必读）

| 情形 | 判定 | 依据 |
|---|---|---|
| 同 lemma，**不同读音** | **不同的词项**（独立摸底/独立反馈/独立判定） | 用户明确要求 |
| 同 lemma，同读音，**不同词性** | **合并为一个词项**（释义拼接展示） | 用户定义「不同读音才算不同的单词」 |
| 旧数据无 `sensesDetail` | 降级为单词级单义项，`pronunciationKey` 用**该词自身读音**（不是空串） | 否则同一词在两种数据形态下 key 不同 → 被判成两个词 |
| 无读音（CMUdict 未命中，86 词） | `pronunciationKey = 'NO_PRONUNCIATION'` | 稳定非空，不与任何读音混淆 |

`normalizeSenses(word)` 是唯一入口；上层永远只处理 `sensesDetail` 一条路径。
